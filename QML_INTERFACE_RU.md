# Первая Qt Quick/QML-оболочка

Новая точка входа: `gui_qml.py`. Резервный `gui_agent.py` сохранён без изменений. Загрузчики, подписи медиа и протокол Agent ради интерфейса не менялись. Предшествующие незакоммиченные исправления ссылок автора сохранены.

## Запуск из корня проекта

Обычный режим, существующий локальный Agent и его клиент:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B gui_qml.py
```

Этот запуск предназначен для пользователя: он использует реальный локальный клиент, ключ Agent и журнал. При первом обнаружении подтверждённого отсутствия службы оболочка может запустить Agent, но не бота. Запуск бота выполняется кнопкой. В ходе разработки обычный режим не запускался.

Безопасная демонстрация без рабочего Agent, ключей, Telegram и загрузок:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B gui_qml.py --demo
```

Демонстрационные состояния: `--demo-state running`, `stopped`, `disconnected`, `busy`, `error`. Данные вымышленные и помечены на экране. Журнал создаётся в TemporaryDirectory, после закрытия удаляется. DemoTransport не создаёт AgentTransport, не вызывает настоящий клиент и не допускает запуска службы.

Скриншот без видимого рабочего окна:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B gui_qml.py --demo --offscreen --screenshot artifacts/qml_overview_running.png --quit-after 1500
```

Параметры автоматического закрытия и скриншота разрешены только с `--demo`. Автоматическое закрытие проходит через тот же механизм ожидания команды, что и крестик.

## Фактический контракт и отображение

- В текущем ответе Agent нет имени бота. Заголовок использует `bot_username`, если он известен, иначе «Telegram-бот». Отображаемое имя не выдумывается, протокол не расширялся.
- `launcher_pid` — PID launcher/watchdog, а не отдельного процесса ядра. Карточка честно показывает «Launcher запущен» и PID watchdog. При подтверждённом `launcher_pid: null` — «Остановлен». До первого подтверждения — «Нет данных».
- Telegram API берётся из поля `telegram_api`: reachable / unreachable / unknown. Это последняя проверка, переданная Agent, а не доказательство текущей доставки медиа.
- Время на экране — время получения ответа оболочкой на этом ПК. Исходное время серверного снимка в протоколе не передаётся. Ответ без новых полей Telegram не подменяется выдуманным результатом.
- При потере связи сохраняются username, PID, состояние API и время последнего успешного ответа. Показываются «Нет связи», «Последнее: …» и «Данные устарели». Старые данные также помечаются после 10 секунд без обновления.

## Потоки и жизненный цикл

- Python-модель: `app/desktop/model.py`; чистое состояние: `state.py`; QML: `app/desktop/qml/Overview.qml`.
- Все обращения к транспорту, чтение журнала и автозапуск Agent выполняются в CommandWorker/QThread. Одновременно допускается одна операция, повторные нажатия блокируются и в модели, и в QML.
- Реальный транспорт использует существующий `local_agent.request`. Для ограничения полного срока вызова он исполняется в собственном дочернем helper-процессе. Сообщения и аутентификация существующего Agent не менялись.
- Helper ограничен 40 секундами ожидания ответа плюс до 5 секунд завершения собственного дерева. Windows Job Object охватывает и посредник Python venv. После истечения срока завершается только этот helper, не Agent и не бот. UI не блокируется ожиданием.
- Автозапуск допускается один раз при начальном обнаружении отсутствия службы. Ошибка ключа сама по себе не считается отсутствием: дополнительно проверяется отказ соединения. Тайм-аут, EOF, ошибка аутентификации, потеря ранее известного Agent и попытка «Выхода» не вызывают повторного запуска службы. Перед запуском отсутствие проверяется ещё раз.
- Крестик не отправляет stop/shutdown. Если команда выполняется, окно остаётся отзывчивым и закрывается только после QThread.finished. Работающий QThread не уничтожается и не завершается принудительно.
- «Выход» отправляет существующий shutdown и закрывает окно только при `ok: true` с явно переданным `launcher_pid: null`. Ошибка или неполный ответ оставляют окно открытым. Ошибка выхода не исчезает после фонового опроса; новый ручной запрос позволяет её сбросить. При ошибке выхода крестик во время этой команды также не скрывает неподтверждённую остановку.
- Журнал ограничен 200 строками: до 150 строк runtime.log и до 50 событий оболочки. Читается только хвост до 64 KiB; строки ограничены по длине и выводятся как PlainText.

## Проверки и ограничения

`tests/test_qml_overview.py` проверяет контракт, потерю связи и сохранение данных, ограничения команд, отсутствие автозапуска на ошибках, отзывчивость и закрытие при зависшем синтетическом helper, подтверждённый/неподтверждённый shutdown, ограничение журнала и offscreen-загрузку QML во всех пяти состояниях.

Qt-проверки используют только подменённый транспорт и временные данные. Включены защиты `offline_support`: запрет чтения .env/.key, записи рабочих data/temp_downloads и соединений с сервисами. Как и в остальных asyncio-тестах, допускается только внутренний socketpair стандартной библиотеки для пробуждения event loop Windows.

Шрифты для offscreen-превью читаются из уже установленного набора Windows. Ничего не устанавливается и шрифты не копируются в проект.

Рабочие Agent, бот, GUI Widgets и сеть при реализации не запускались. Взаимодействие нового интерфейса с настоящей службой остаётся ручной проверкой. Серверный режим, мультиботность и EXE не добавлялись. Коммит и push не выполнялись.

## Результаты реализации

- Основной автономный набор: **90 тестов, OK**, включая **21 новую проверку** QML/модели/транспорта. Полный набор запускался с `-W error::ResourceWarning`.
- Во всех пяти состояниях QML загрузился без предупреждений QML, скриншоты непустые; дополнительно изображения просмотрены визуально.
- После визуальной проверки уточнены offscreen-шрифты и перенос длинного состояния на две строки. Используются уже установленные Segoe UI и Consolas; файлы шрифтов не копировались и не устанавливались.
- Проверка зависшего синтетического helper подтвердила ограничение времени, отзывчивость Qt-таймера и закрытие только после завершения QThread. Проверены отсутствие повторного автозапуска после потери ранее известного Agent и сохранение ошибки выхода после фонового опроса.
- У установленной связки PySide6/Python есть предупреждение GC при завершении интерпретатора: 22 uncollectable objects для 22 Qt Property модели. Оно воспроизведено простым импортом класса без приложения, потоков, транспорта или процессов. Минимальный независимый класс QObject с одной Property даёт такое же предупреждение об одном объекте, как с lambda, так и с именованным getter. Это не ошибка QML-загрузки и не свидетельство уничтожения работающего QThread. Предупреждение не скрывалось; пакеты не обновлялись. Требуется отдельная проверка совместимости библиотек вне текущих ограничений.

## Обновление оформления: тёмное стекло

Сначала повторно проверено исправление фонового опроса: 28 проверок модели/оболочки прошли до изменения оформления. Опрос остаётся раз в 2 секунды, не включает видимый busy и не блокирует кнопки. Очередь ручной команды, отдельные notify-сигналы свойств и ожидание QThread при закрытии сохранены.

Новая палитра и размеры собраны в `app/desktop/qml/Theme.qml`: фон #0D1015, текст #F2F0EB, шампань #C7B38A, успех #65CBB8, ошибки #EF8F8F. Плавающая навигация и панель управления используют стекло, карточки состояния и журнал — более плотный читаемый фон. Панели имеют радиусы 20–24 px. Анимации цвета при наведении и нажатии — 180 мс; непрерывных декоративных анимаций нет. Активный индикатор команды сохраняется только для ручных действий.

Компоненты: `AmbientBackground.qml`, `GlassPanel.qml`, `PillButton.qml`, `StateCard.qml`, `Theme.qml`, регистрация singleton в `qmldir`. Фон содержит только три статичных радиальных градиента и перерисовывается при изменении размера. Текст не входит ни в один источник эффекта. Прозрачность задаётся цветам фона/кромки, а не opacity компонента с надписями. Клавиатурный фокус имеет явную кромку шампань.

Установлены Qt/PySide6 6.11.2 и QtQuick.Effects.MultiEffect. Нативный Direct3D 11 проверен тестовым окном: оба ShaderEffectSource захватывают только `ambientBackground`, `recursive: false`, `live: false`; обновление выполняется при геометрии/прокрутке и перерисовке фона. Размытие ограничено областями стекла, захваты используют половинное разрешение. Кэш не включает foreground и не захватывает сам стеклянный компонент.

Лёгкий вариант включается автоматически на программном рендерере, либо явно:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B gui_qml.py --lite
```

В нём остаются дымчатые градиенты, блик и кромка, но shader-захваты/blur отсутствуют. Режим проверен и на нативном Direct3D 11 при всех трёх масштабах.

Журнал по умолчанию показывает последние 3 строки. Кнопка «Развернуть» открывает весь ограниченный журнал (до 200 строк). На узком окне навигация становится компактной; в низком окне уменьшаются только отступы. При нехватке высоты страница прокручивается; основные команды остаются в области окна. Длинный username не меняет ширину панелей: используется многоточие в середине и подсказка с полным текстом. PID оставлен второстепенным. Шрифты читаются из имеющегося набора Windows с fallback Segoe UI → Arial → Tahoma, без установки или копирования в проект.

### Проверки оформления

- Полный набор: **102 теста, OK**; из них **33 проверки QML/модели/транспорта**.
- Пять состояний × 3 масштаба = **15 offscreen-превью**, с проверкой фактического сценария, DPR, размеров PNG и расположения всех кнопок.
- **3 нативных GPU-превью** при DPR 1 / 1,25 / 1,5: Direct3D 11, blur включён, в JSON проверены оба источника без рекурсии.
- **3 нативных превью без эффектов** с теми же DPR: blur выключен.
- Контраст основных и второстепенных надписей, акцента и disabled-текста проверен по пикселям итогового отрисованного фона: не ниже 4,5:1. Дополнительно проверены цвета текста основной кнопки и ошибки.
- Проверены Tab/Space-фокус и активация капсул, раскрытие/сворачивание журнала, отсутствие opacity у компонентов с надписями, длинное имя, отсутствие горизонтального переполнения, сохранение поведения команд и закрытия.
- Прежнее GC-предупреждение установленной связки PySide6/Python о 22 Property при завершении интерпретатора сохраняется; оно описано выше и не скрывалось. Рабочие QThread по завершении проверок не оставались.

Целевой размер **1366×768 физических пикселей** проверен при 100%, 125%, 150% в отдельных процессах Qt. Это соответствует примерно 1366×768, 1093×614 и 911×512 логическим пикселям. Учитывается исходный масштаб монитора, фактический DPR записывается в JSON. Настройки Windows не менялись; проверки выполнены эмуляцией DPI приложения, а не ручным переключением масштаба всей системы. На высоком DPI нижняя часть страницы доступна прокруткой. Системная рамка окна зависит от Windows; тестовый размер относится к клиентской области.
