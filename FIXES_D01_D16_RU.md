## Что сохранено и что изменилось в эксплуатации

- Архитектура GUI → Agent → watchdog → бот сохранена; worker расширен на Instagram и метаданные.
- Закрытие окна по-прежнему оставляет Agent и бота работающими; «Выход» выполняет локальный shutdown. Само окно и рабочая цепочка в этой сессии не запускались.
- Мультиботность, серверный режим и QML не добавлялись.
- Протокол Agent изменился: старый и новый клиент/Agent несовместимы. Перед ручной проверкой пользователь должен штатно завершить прежний Agent и запускать обновлённые GUI/Agent вместе. Работающие службы в этой сессии не останавливались.
- Windows Job включает и посредник `.venv`, и его интерпретатор: CREATE_SUSPENDED исключает создание потомка до установления владения. Для возобновления применяется NtResumeProcess; работоспособность проверена на текущей Windows, другие версии Windows не проверялись.
- Для Linux сохранена схема процессных групп и добавлен сигнал смерти родителя в bootstrap, чтобы отдельная группа дочернего процесса не оставалась без родителя. Linux-выполнение не проверялось; серверный режим не реализован.
- Worker требует локальные ffmpeg и ffprobe для медиа. Они уже присутствовали; пакеты и инструменты не устанавливались.
- Совместимые файлы не перекодируются. Неподходящий результат перекодируется внутри worker с пределом времени 300 с; ffprobe ограничен 30 с. При слишком большом или усечённом результате возвращается ошибка, без выдачи неполного файла за успех.
- Очередь ограничена числом пользователей/обработчиков, а не новой серверной инфраструктурой. Ожидающие Telegram-обновления остаются вне активных обработчиков polling.
- Автоочистка не касается прежних немаркированных temp_downloads/<user>/<job>. Их содержимое не исследовалось и не удалялось. Новая схема не объявляет очистку успешной заранее.

- Настоящие GUI/Agent не запускались. Аутентификация, тайм-ауты и обработка команд проверены с подменами, а не реальным loopback-соединением. Визуальная отзывчивость и полный shutdown требуют ручной проверки.
- Принудительная остановка Windows надёжно завершает принадлежащие процессы, но не гарантирует выполнение finally в убитом процессе. Поэтому остаётся отложенная уборка маркированных файлов.
- Бюджет каталога и свободное место проверяются периодически в download hook; это прикладной контроль, не файловая квота ОС. Размер окончательного результата проверяется дополнительно. Внешние приложения могут одновременно занять диск.
- Перекодирование может увеличить время подготовки и CPU-нагрузку; worker и FFmpeg имеют сроки выполнения. Автоматического понижения качества до гарантированного попадания в размер не добавлено.
- При обрыве отправки сервер мог принять файл; автоматический повтор намеренно отсутствует, пользователю предлагается проверить чат.
- Python/библиотеки/FFmpeg не обновлялись. Серверные сценарии и другая Windows-среда не объявляются проверенными.
